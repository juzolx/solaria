# Fable review: DUNGEON area, round 1 of 5 (2026-10-25)

Reviewer: Fable 5.1. Branch big-update 7b1daf7a (halls merged). Judged from the shipped art (`art/halls`, `art/props`, `art/people`, `art/traps`, contact sheets built at 3-4x nearest), the code (`room3d.gd`, `room_view.gd`, `halls_scene.gd`, `battle_view.gd`, `sprite_light.gd`, `halls.gd`), the style bible, `claude/zone-palettes.md`, `art-ratings.md`, and the last in-game phone shots (`shots/room3d/fight.png`, Oct 19, still the old monsters). No new in-game shots of the Oct 24 halls exist on big-update (the halls worktree is gone), so round 2 needs `tests/_halls_zone_shot.gd` and `tests/_room_events_shot.gd` run for zones 0, 5 and 9 at 430x932.

Phone geometry used below (430x932, HallsScene): focal = 0.62 x 430 = 266 px; a point at depth z is on screen only if |x| < 0.806 z (world units; the room is 6 wide, so x runs -3..3). Far-wall floor line sits at y = 0.32 h; the monster ground (0.58 h) is at z = 2.4.

## Problems, worst first

1. **The torches and shrine braziers are off the phone screen, so the light comes from nowhere.** `room3d.gd:581-586` puts Overgrown-hall torches at x = +-2.92, z = 3.58 (visible limit at that depth: 2.88); `room3d.gd:644` root-choked torch at x = -2.92, z = 3.0 (limit 2.42); `room3d.gd:627-630` shrine braziers at x = +-2.0, z = 1.8 (limit 1.45). `room3d.gd:481` urn at x = 2.55, z = 2.5 (limit 2.0), `:485` skeleton at 2.55 / 2.1 (limit 1.7), `:482` barrel/crate at 2.5 / 3.4 (limit 2.74). Only the 2D fallback's torches (`halls_scene.gd:97-99`, z 3.9-4.6) are visible. Fix: every placement must satisfy |x| <= 0.78 z (keep a margin for the vignette): torches at z >= 3.9 on the side walls, braziers at x = +-1.5, z >= 2.2, wall props at z >= 3.5. Add a one-line `assert(absf(pos.x) <= 0.78 * -pos.z)` helper in `_sprite`/`_torch` so it can't regress.

2. **Far-wall textures are minified below 1 texel per pixel: skulls, cracks and leaf carvings turn into shimmer.** Materials are triplanar at one 32 px tile per world unit (`room3d.gd:_mat`, default `uv1_scale`), the far wall is 6 x 4 units = 192 x 128 texels, but on a phone it spans 291 screen px, and the SubViewport renders at half size (`PIX := 2.0`, `room3d.gd:14`), so 145 viewport px cover 192 texels (0.76 px per texel, nearest filtered = sparkle). The style bible's "one 3x integer scale" is impossible there. Fix: `m.uv1_scale = Vector3(0.5, 0.5, 0.5)` (one tile per 2 units: the far wall is then 96 texels over 145 vp px = 3 screen px per texel, the bible's 3x, with nearer walls going bigger as perspective must) and render the viewport at `PIX = 3.0` so backdrop pixels are the same size as the 3x sprites. Do the same in the 2D fallback (`halls_scene.gd:168-176` tiles the floor once per 0.5-unit quad, twice as fine as the walls).

3. **The 3D backdrop is a soft haze over pixel art: fog + bloom + filmic tonemap + additive mist quads + additive light cones, then the battle view paints two more fog layers and three light shafts on top.** `room3d.gd:_environment` (fog 0.045-0.095, glow 0.7, TONE_MAPPER_FILMIC), `_mist_layer` (NoiseTexture2D additive quads, every room type but shrine/collapsed), `_shaft` (additive cone + unshaded hole disc), then `battle_view.gd:2043-2075 _draw_mood` (3 additive polygons + 2 scrolling fog strips). `shots/room3d/fight.png` shows the result: no readable wall or floor, a grey-blue smear. The bible says no soft gradients, no blur. Fix: fog off (or <= 0.02 with a near-black colour), glow off, `TONE_MAPPER_LINEAR`, delete `_mist_layer` and `_shaft` (replace the shaft with a 4-step dithered quad if a hole in the ceiling is wanted), and in the battle view draw `_draw_mood` only when `not halls.is_3d()`.

4. **Zone-0 dressing leaks into all ten zones, so Cinder Abyss and the Gilded Spire get green moss, daylight shafts and cobwebs.** `room3d.gd:rebuild` calls `_moss_patches(1)` (green ramp hard-coded in `moss_tex`) and `_cobwebs()` for every zone; `_overgrown_hall` rolls a 45% daylight shaft and `_collapsed_chamber` always has one, both with hard-coded daylight colours `#b3d3b5` / `#d8e8d0` (`_shaft`); `_shell` tints every far wall `Color(0.62, 0.66, 0.6)` and ceiling `(0.75, 0.78, 0.75)` (green-grey); the shrine rune is always cyan `(0.45, 1.15, 1.3)` with a `#5ad1e6` light and the portal light is always `#d05ad8`. None of those colours are in `art/palette.gpl`. Fix: moss and shaft only when `zone == 0`; shaft colour = `light_col`; wall/ceil tints neutral grey; shrine rune and portal light = the zone's Accent from `claude/zone-palettes.md` (put that table in code as `HallsScene.ACCENT[zone]`).

5. **Zones 1-9 share three room kinds that are all Mossy Hollows ideas ("Overgrown hall", "Collapsed chamber", "Forgotten shrine"), so apart from the wallpaper every zone is the same three rooms.** `room3d.gd:12 KINDS_OTHER`. The zone motifs the owner approved (water, lava seams, runes, pipes, gold coffers, spikes) exist only inside 32 px tiles. Fix: one signature dressing per zone, cheap and flat: z2 a puddle quad (floor texture darkened, `#4fb0c6` light at floor level), z3 glowing crack strips (`_flat` with `#e43b44` additive, 2-step), z4 a carved-eye sprite on the far wall, z5 pale ghost wisps instead of torches, z6 crystal shards (`#c27ad8`) at the wall feet, z7 a brass pipe run along one wall (a long `_box` with `z7_wall` tinted), z8 gold pillars, z9 spike rows. Rename the kinds per zone so the shot script and future notes read right.

6. **Pixel density of billboard props is random: the same 40 px canvas is stretched to 0.25-1.6 world units, so a candle's pixels are 7x smaller than a statue's next to it.** `room3d.gd:_sprite` sets `pixel_size = height / tex.height`; callers pass 0.25 (skull), 0.28-0.4 (candles), 0.5 (chest), 0.6 (urn, barrel), 1.0 (brazier), 1.6 (statue), 2.25 (door, 42 px). In one shrine the candles, bones, statue and door all have different pixel sizes. Fix: one constant `PX_UNIT := 1.0 / 20.0` (a 40 px prop = 2.0 units? no: pick 1/24 so a 40 px prop stands 1.67 units, a 64 px person 2.67... too tall) - practical choice: `pixel_size = 1.0 / 32.0` for every prop and door (door 42 px = 1.3 units high, matching DOOR_W; a 40 px chest = 1.25 units, a 24 px candle cluster = 0.75). Then size the ART, not the sprite: crop/redraw tiny things (skull, candles) smaller on their canvas. Same rule for `_torch` (0.6 units for a 32 px torch = 1/53 per px, far too small; at 1/32 it is a 1-unit torch).

7. **People and props in the 2D room view are drawn at non-integer scales (1.2x-3.7x), and the heroes jump from 2x in the room to 3x in the fight.** `halls_scene.gd:sprite` sets `hpx = focal * h / z` (stranger h 1.4 at z 1.7-5.0 = 75-220 px for a 64 px picture); `room_view.gd:_draw_team` draws the leader at `size * 2.0` and companions at `* 1.7`, while `battle_view.gd:_unit` uses `ArtStyle.unit` (3 on a phone). The bible: every sprite at the same integer scale, nothing scaled by a non-integer. Fix: in `_draw_prop` snap `hpx` to `64 * k` (k = 1, 2 or 3) by picking k from the depth band and solving z from k (people stand on one of three depth rows), and in `_draw_team` use `ArtStyle.unit()` for the leader and `unit - 1` for companions (whole numbers only).

8. **Trap and shrine circle: a hexagram, 1 px lines, rotated per frame.** `art/traps/circle.png` is a Star of David inside two rings (a real religious symbol; App Store reviewers and players will read it as one). `room_view.gd:_draw_trap` spins it (`spin = t * 0.4`) through 64 polygons each frame, so the 1 px rings rotate sub-pixel and crawl; the shrine (`room3d.gd:_forgotten_shrine`) uses the SAME circle in cyan, and a frost rune (`Halls.TRAPS.frost.color #2ce8f5`) is also cyan: shrine and frost trap are the same picture. Fix: redraw `circle.png` as Solaria's own glyph (a 2 px ring, runic ticks, a different inner sigil per trap kind baked into six small 64 px sheets, or one base + a 16 px centre icon), no rotation (pulse the colour instead), and give the shrine its own glyph (the altar's rune from `art/props/altar.png`).

9. **Door art does not fit the arch: ten doors, six different sizes, all stretched to the same height.** Sizes: z0 32x42, z1 32x43, z2 32x43, z3 28x40, z4 24x40, z5 32x48, z6 32x43, z7 32x45, z8 32x44, z9 32x44 (fallback `door.png` 32x48). `room3d.gd:_shell` draws each at `dh * 0.98` tall, so the 32x42 doors come out 1.71 units wide inside a 1.3-wide arch (30% of the frame, including the carved stone jambs, is cut off by the CSG arch), while z4 at 24x40 fits. The 2D fallback (`halls_scene.gd:draw_doors`) squashes `door.png` (0.667) into the 0.565 door rect, and never uses the zone doors at all. Fix: one door canvas for all zones, 32x56 (= DOOR_W : DOOR_H 1.3 : 2.3, with a rounded top matching `arch.radius`), re-fit the ten doors to it (PixelLab outpaint or hand-fix), draw them at pixel_size 1/24.6 so 1.3 units = 32 px exactly, and have `draw_doors` use `_zart`'s zone door too.

10. **The champion portal is a 30x42 picture clipped by the arch and blown out by `modulate (1.3, 1.2, 1.3)`, while the rift event is still a code-drawn gradient blob in Tailwind purples.** `room3d.gd:_shell` (portal sprite, unshaded, over-bright, fixed `#d05ad8` light), `room_view.gd:_draw_rift/_draw_portal` (6 nested alpha ellipses `#3b0764`->`#c4b5fd`, neither in the palette, plus 10 orbiting dots and a white core). Two portals, two styles. Fix: fit `portal.png` to the same 32x56 door canvas as item 9 with its stone frame inside the arch, modulate 1.0 (let the art carry the glow, add a 2-frame flicker by swapping two PNGs), and draw the rift with a 48x64 rift sprite in the same style (`#9a4fc0` / `#c27ad8` / `#e8b8f0` ramp from the "scale" material) with a 3-frame loop; delete `_draw_portal`.

11. **The hall tiles repeat visibly as wallpaper on big flat walls: z1 skull every 32 px, z5 bright leaf carving, z7 pipes grid.** Contact sheet `halls_tiled.png` (3x3 of each): z1 wall has an identical skull in every tile; z5 (Hushwood) wall is a saturated `#566a56`/`#75a743` carved repeat, the brightest surface in the game, while `zone-palettes.md` says Hushwood is ghost-pale and dead silver wood; z9 wall and floor are the same crimson-crack texture, so the floor/wall corner vanishes. Fix: for z1 and z7 make a plain variant tile and let the material pick plain vs motif per 2x2 unit (two materials on alternating `_box` strips, or one 64x64 texture with the motif in a single quarter); darken z5 wall to the zone Dark/Mid (`#1f1d24`, `#193c3e`, `#566a56` only as carving highlight); give z9 a distinct floor (black basalt with few embers, like z3's floor) so the wall reads as a wall.

12. **Two near-identical smiths: the travelling smith Gilda (`art/people/smith.png`) and Hilde the town smith (`art/people/hilde.png`) are both red-braided dwarf women in a leather apron with a hammer.** A player meets Gilda in a room and then sees "Hilde" at home with the same face. Fix: redraw Gilda as a different person (dark hair under a hood, pack and bedroll, hammer on the belt) or make the traveller an apprentice of Hilde and say so in `Travelers.LIST`.

13. **Prop labels in the room are 10 px (about 8.5 pt on a 430 pt phone); the room message is 14 px; the floor title 13 px.** `room_view.gd:_draw_prop` (`draw_string ... 10`), `_draw`. The owner's rule (ratings row 57): names must be easier for everyone to read. The battle view already uses `NAME_FS := 18`. Fix: labels 16 with the 5 px outline, message 16, title 16, same font (`UI.game_font()`) as the battle view instead of `get_theme_default_font()`.

14. **Three colour systems describe one zone's light: `GameData` zone colour (Tailwind, e.g. `#4d7c0f` lime-700), `HallsScene.MOODS` light/amb (none in the palette: `#ffd27a`, `#a8e6ff`, `#c9a3ff`, `#b8f5d0`, `#ffb3f0`, `#fff4c2`, `#ff4a4a`), and `zone-palettes.md`.** `battle_view.gd:_rim_color` lerps the GameData colour with `#fff4d6` for the hero rim and the fog; `SpriteLight.lit` uses MOODS; the 3D lights use MOODS; the halls art uses the palette. Zone 6 MOODS amb `#b49ab8` is the lavender the palette note forbids; zone 8 light `#fff4c2` + dark 0.2 is the white/pastel it forbids. Fix: one table (Dark/Mid/Accent/Light per zone, palette colours only) in `HallsScene`, and `GameData` zone colour, `_rim_color`, MOODS and SpriteLight all read from it.

15. **`SpriteLight.lit` re-shades every new monster with a blurred-silhouette normal map (box blur radius ~6, "soft, painterly" WRAP 0.5) and a 30% ambient tint, on top of DarkGrade.** `battle_view.gd:1594` and `:1551`, `sprite_light.gd:shade`. The monsters the owner rated "amazing" were drawn with 3-5 hue-shifted shades and lifted mid-tones for readability; the gradient wash flattens those ramps and the rim adds a second outline colour. It also costs a GDScript per-pixel pass the first time each monster shows in each zone (a 120x120 boss = ~14k pixels x 4 blur passes = a visible hitch on a phone). Fix: skip SpriteLight for art with `"hd": 1` (native redraws) and keep at most a 1 px rim in the zone accent; or move the shade to a shader so it is free.

16. **Per-frame cost on a phone: up to 7 shadow-casting lights every frame in a SubViewport set to UPDATE_ALWAYS.** `room3d.gd:_torch` (`shadows = true` per torch, 1-4 per room), `_forgotten_shrine` braziers (shadows), `_shaft` SpotLight (shadows), `_init` shadow atlas 1024, plus 24-66 CPUParticles3D (`_region_particles` + `_root_choked` adds 30 more), CSG far wall rebuilt per room, a fresh `NoiseTexture2D` (threaded 128x128 generation) and fresh `StandardMaterial3D` instances per rebuild. Omni shadows are the dearest thing a mobile GPU does (6 faces each). Fix: `shadow_enabled = false` on every OmniLight (keep one spot shadow at most, only in Collapsed chamber), cap particles at 24 per room and drop `_root_choked`'s extra emitter, cache one seamless noise texture and the materials in `_texcache` keyed by path+tint, and in the room view (not the fight) render the viewport every other frame (`UPDATE_ONCE` on alternate `_process` calls) since only the flicker moves.

17. **Code-drawn 3D geometry inside pixel rooms: 6-sided smooth cylinders for roots (`_root`, zone 0 Root-choked and corner roots), triplanar rubble boxes rotated 0-40 degrees (`_rubble`) that smear the wall texture across their faces.** The owner's own words on round 2-3: "code-drawn stiffness". Fix: roots as flat `_flat` quads with a 16x48 vine/root sprite (there is already `vine_tex`; draw a proper root PNG in `art/halls/z0_root.png`), rubble as 2-3 `boulder.png` / `pillar_broken.png` billboards at the collapse.

18. **Town keepers (in scope: the owner asked for these people) show at 1x (64 px on a 430 pt phone) next to 3x heroes.** `main.gd:735` ("2x pushed the Tavern page off a phone"). A 64 px figure at 1x is a thumbnail; the bible says one integer scale. The smithy picture (`craft_tab.gd:41`) is 56x56 for 64 px art (0.875x) but hidden. Fix: 2x (128 px) with the keeper in the talk row's left column spanning the name + line (the line wraps beside it), and delete the dead `smith_pic`.

19. **Soft code glows under pixel art: campfire (5 alpha ellipses), camp lantern (2 circles), 2D torch (4 circles), drop shadows (`shadow`, 0.4 alpha ellipse), door-read glow ellipses.** `room_view.gd:_draw_campfire`, `_draw_camp`, `halls_scene.gd:draw_scenery`, `shadow`, `draw_doors`. Fix: one 32x16 dithered glow PNG (3 alpha steps) tinted per use, and a 2-step dithered shadow sprite; no `draw_circle` with alpha in the room.

20. **Missing fallbacks / guards:** `room3d.gd:_shell` loads `art/halls/z%d_wall.png`, `_floor`, `_ceil` with a bare `load` (a missing file = null albedo = flat white box with no message), `prop()` likewise; `halls_scene.gd:build` uses `MOODS[zone]` with zone clamped but `GameData.zone_for_floor` names are not checked against the ten halls; `Room3D.rebuild` runs `_zone_props` chest/altar only for z1 (the other nine zones silently have none because `_zart` returns null). Fix: `_zart` for the shell too, with `art/halls/door.png`-style shared fallbacks and a `push_warning`, and the art-rules test asserting every zone has wall/floor/ceil/door/torch (it already does for props).

## Score: 5 / 10

The raw pieces are good (the ten tile sets, the 25 props, the 18 people are all on style and palette, and the owner has rated them), but what reaches the phone is not: the lights are off-screen, the far wall is minified into noise and then fogged, every zone wears Mossy Hollows' moss and daylight, and nothing in the room shares a pixel size. The bible's one rule ("one 3x integer scale, no blur") is broken by the backdrop itself.

## Biggest opportunity

Make the 3D room a pixel room: render at PIX = 3, tile textures per 2 units, kill fog/glow/mist/shafts, one pixel_size for every prop and door, lights where the phone can see them, zone accent colours from one table. Those six changes (items 1-6) are code-only, cost no PixelLab credits, and would let the approved hall art finally look on a phone like it does on the contact sheet.
